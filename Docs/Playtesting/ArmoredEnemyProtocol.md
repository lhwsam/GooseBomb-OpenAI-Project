## 이번 세션이 답할 질문

1. 설명 없이도 첫 폭발이 갑옷만 파괴했고 적이 아직 살아 있다는 사실을 즉시 읽는가?
2. 첫 피격 뒤 외형 변화와 바닥 3칸 예고를 같은 상태 변화로 이해하고 달릴 방향·도착점을 예측하는가?
3. 예고된 도착점 또는 그 영향 셀에 두 번째 폭탄을 선행 설치하도록 위치·시점·퇴로를 새로 계획하는가?
4. 두 번 맞히기가 의미 있는 단계 전투인가, 같은 행동을 반복하는 체력 2 적인가?
5. 느린 반경 수비→빠른 panic→짧은 회복→공격 추격을 구분하고 대응할 시간이 충분한가?
6. 기본 추격자와 장갑병의 피해 원인·위치·처치 상태를 구분할 수 있는가?
7. T 교차점의 상단 막·좌우 가지·남쪽 포켓이 첫 폭발 방향과 두 번째 유도 선택을 만들면서 시작 직후 불공정한 접촉을 유발하지 않는가?

자동 검증은 서로 다른 두 `BombId`, `Armored/Guard → Broken/PanicTelegraph → PanicRun → PanicRecover → Chase → Dead`, 폭발 중심 기반 고정 경로, 시간 경계와 점유 제거를 보장한다. 경로가 읽히는지, 두 번째 폭탄을 실제로 선행하게 만드는지와 반복 노동감은 사람 관찰로만 판정한다.

## 고정 조건

- Unity 6000.5.3f1 Development WebGL, 갑옷 방 시작 전용 빌드.
- 플레이어 `(0,-2)`, 기본 추격자 `(4,4)`, 갑옷 적 `(0,1)`.
- T 교차점 고정 벽: 남쪽 통로 `(-2,-2)·(2,-2)·(-2,-1)·(2,-1)`, 상단 막 `(-1,2)·(0,2)·(1,2)`, 좌우 종단 `(-4,0)·(4,0)`. 파괴 가능 벽과 돌진형 없음.
- 장갑병: 접촉 피해 1, `Guard` 1 cell/s·spawn 반경 1, `PanicTelegraph` 0.6초, `PanicRun` 6 cells/s·최대 3칸, `PanicRecover` 0.5초, `Chase` 3 cells/s·방향 유지 2칸, 서로 다른 폭발 2회에 사망.
- 추격자: 내구도 1, 접촉 피해 1, 2 cells/s, 방향 유지 2칸.
- 플레이어 이동 5 cells/s, 최대 체력 5, 자기 폭발·접촉 피해 1, 공유 무적 0.75초.
- `prototype-cross`: 십자, fuse 2초, 범위 2, 설치 쿨타임 1.5초.
- `prototype-area`: 3×3 광역, fuse 1.75초, 범위 1, 설치 쿨타임 2.5초. 교체 쿨타임 2초.

세션 도중 수치, 코드, 방 데이터와 설명 수준을 바꾸지 않는다. 다른 commit이나 빌드의 결과는 같은 조건으로 합치지 않는다.

## 참가자와 시도

- 내부 참가자 1~3명, 한 명당 5~10분.
- 한 시도는 갑옷 방의 모든 적을 처치하거나 사망할 때까지다. 한 사람당 최대 3회다.
- 첫 시도는 상태 의미와 최적 위치를 설명하지 않는다.
- 두 번째 시도는 “첫 폭발 전후에 설치 위치나 퇴로를 달리해도 됩니다”만 허용한다.
- 세 번째 시도는 참가자가 다른 폭탄이나 유도 계획을 자발적으로 확인하고 싶을 때만 수행한다.
- 새 시도는 페이지 reload로 동일 초기 상태에서 시작한다.

## 시작 안내

다음만 알려준다.

> 이동은 WASD 또는 방향키입니다. Z로 현재 폭탄을 설치하고 X로 두 폭탄을 교체할 수 있습니다. 방의 적을 모두 처치해 보세요. 피해를 최소화하면서 원하는 방식으로 플레이해 주세요.

- 장갑병의 피격 횟수, 색·크기·바닥 예고 의미, panic 방향과 추천 폭탄 위치는 설명하지 않는다.
- 첫 폭발 직후 질문하지 않는다. 놀람·멈춤·접근·이탈·즉시 재설치 같은 자발적 반응을 먼저 기록한다.
- 첫 시도가 끝난 뒤에만 참가자가 무엇이 바뀌었다고 생각했는지 묻는다.

## 실행 순서

1. 세션 ID, commit, WebGL 산출물, 브라우저·해상도와 참가자 경험을 기록한다.
2. Console 오류가 없고 `prototype-combat-armor`가 시작 방인지 확인한다.
3. 첫 시도는 중간 설명 없이 관찰한다. 첫 폭발 전 설치 위치·퇴로와 첫 폭발 뒤 예고 0.6초 및 질주 종료까지의 반응을 시간 순서로 기록한다.
4. 예고를 처음 알아차린 시점, 예상한 방향·도착점, 두 번째 폭탄의 실제 설치 셀과 폭발 시 장갑병 위치, 회복/추격 중 피격 여부를 기록한다.
5. 시도 종료 직후 아래 인터뷰를 진행한다. 발언을 관찰 사실과 분리한다.
6. 두 번째 시도는 다른 계획을 허용하되 정답 위치를 알려주지 않는다.
7. [전용 기록 템플릿](ArmoredEnemySessionTemplate.md)에 사실·발언·해석과 `Keep / Change / Drop / Insufficient evidence`를 분리해 기록한다.

## 핵심 관찰표

| 시점 | 관찰할 행동 | 해석 시 주의 |
|---|---|---|
| 첫 폭탄 설치 전 | 어느 적을 목표로 했는지, 설치 뒤 어느 퇴로를 택했는지 | 우연한 동시 적중을 의도적 선택으로 기록하지 않는다 |
| 첫 폭발 직후 예고 0.6초 | 시선/이동 정지, 바닥 경로 회피·추종, 방향/도착점 언급, 즉시 재설치 | 붉은 폭발 셀과 panic 예고 셀을 혼동했는지 분리한다 |
| `PanicRun` | 실제 질주 방향과 예측 일치, 경로를 가로막거나 도착점으로 이동, 순간이동/불공정 언급 | 단순 도주와 도착점 선점 계획을 구분한다 |
| `Recover → Chase` | 회복 창 인지, 폭탄 설치·거리 확보, 추격 전환 인지 | 회복을 AI 정지/오류로 오해했는지 확인한다 |
| 두 번째 폭탄 설치 | 첫 설치와 다른 셀·시점·퇴로이며 예고 도착점과 관계가 있는지 | 다른 위치가 T 벽 때문인지 예고를 읽은 결과인지 질문한다 |
| 사망/클리어 | 두 번째 적중과 사망을 연결했는지 | 추격자 사망과 갑옷 적 사망을 혼동하지 않았는지 확인한다 |

명확한 “계획 변화”는 첫 피격 뒤 설치 위치·시점·폭탄 종류·퇴로 중 하나를 바꾸고, 예고 방향·도착점 또는 회복 창과 연결해 설명한 경우다. 단순히 적에게서 멀어진 행동만으로 전략 변화라고 판정하지 않는다.

3. 두 번째 폭탄은 첫 번째와 비교해 위치·타이밍·퇴로를 바꿨나요? 예고된 도착점이 선택에 영향을 줬나요?
4. 두 번 맞히는 과정이 새 계획을 요구했나요, 같은 행동의 반복이었나요?
5. 빠른 질주, 짧은 멈춤, 이후 추격이 각각 다른 단계로 느껴졌나요?
6. 장갑병과 기본 추격자의 이동·피해·사망을 구분할 수 있었나요?
7. 첫 피격 뒤 피해가 불공정하게 느껴진 순간이 있었나요? T 갈림길에 피할 정보와 공간이 충분했나요?
8. 한 가지만 바꾼다면 예고 시간·표현·질주 속도/거리·회복 시간·방 배치·필요 피격 횟수 중 무엇인가요?

|---|---|---|---|
| 첫 피격 가독성 | 첫 1~2회 안에 갑옷 파괴와 생존을 설명 없이 구분 | 살아 있음은 알지만 색·크기 의미나 피격 확정이 모호 | 사망/무효 폭발로 오해하거나 상태 변화를 반복해서 못 봄 |

| 두 번째 폭탄 계획 | 예고 도착점/회복 창에 맞춰 설치 위치·시점·폭탄·퇴로가 달라지고 이유를 설명 | 행동은 달라지지만 예고와의 인과가 불명확 | 같은 자리·같은 순서를 반복하며 체력 2 노동으로 느낌 |
| panic·회복·추격 리듬 | 세 단계를 구분하고 대응할 시간이 충분함 | 한 단계가 너무 짧거나 정지로 오해 | 순간이동·입력 지연·불공정 추격으로 반복 설명 |
| 두 적 구분 | 목표·피해·사망 원인을 구분해 우선순위를 선택 | 시각 중첩이나 HUD 부재로 가끔 혼동 | 어떤 적이 맞고 죽었는지 지속적으로 구분 못 함 |
| T 교차점 배치 | 첫 적중 재현과 좌우 가지·남쪽 포켓의 선행 설치 선택을 모두 제공 | 한 가지가 항상 정답이거나 시작 압력이 높음 | 시작 직후 회피 불가 또는 두 번째 계획 공간이 없음 |
