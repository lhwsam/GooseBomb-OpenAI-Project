## 이번 세션이 답할 질문

1. 프레임 연속 이동으로 바뀐 뒤 키 해제와 빠른 `상 → 우` 반복이 즉시 반응하는가?
2. 십자 폭탄과 3×3 광역 폭탄이 실제로 다른 설치 위치와 교체 시점을 만드는가?
3. 두 번째 방의 대각선 파괴 블록과 세 번째 방의 중앙 블록이 퇴로·유도·폭탄 선택을 바꾸는가?
4. 돌진형의 예고 시작, 잠긴 직선 방향, 돌진 종료와 회복 상태를 설명 없이 읽고 피할 수 있는가?
5. 플레이어가 돌진선 또는 회복 위치를 예상해 폭탄을 미리 설치하는가?
6. 추격자와 돌진형의 동시 압력이 어렵더라도 공정한가, 아니면 피해 원인을 분리하기 어려운가?

자동 검증은 입력 전달, 상태 순서와 충돌 규칙을 보장한다. 위치 선택, 가독성, 공정성과 재미는 참가자의 행동과 직후 설명으로만 판정한다.

## 고정 조건

- Unity 6000.5.3f1 Development WebGL.
- 플레이어 이동 5 cells/s. 별도 0.2초 step·pending turn·Transform 목적 셀 보간은 없다.
- `prototype-cross`: 십자, fuse 2초, 범위 2, 설치 쿨타임 1.5초.
- `prototype-area`: 3×3 광역, fuse 1.75초, 범위 1, 설치 쿨타임 2.5초.
- 슬롯 교체 쿨타임 2초. 시작 활성 슬롯은 십자 폭탄이다.
- 추격자: 내구도 1, 접촉 피해 1, 2 cells/s, 방향 유지 2칸.
- 돌진형: 마지막 방에만 존재, 내구도 1, 충돌 피해 1, 예고 0.75초, 돌진 8 cells/s, 회복 0.75초.
- 플레이어 최대 체력 5, 자기 폭발·적 접촉 피해 1, 공유 무적 0.75초.
- 방과 spawn의 정확한 셀은 [방 저작과 검증](../Systems/RoomAuthoring.md)을 따른다.

세션 도중 위 수치, 코드와 방 데이터를 바꾸지 않는다. 다른 commit이나 빌드의 결과는 같은 조건으로 합치지 않는다.

## 참가자와 시도

- 내부 참가자 1~3명, 한 명당 10~15분.
- 한 시도는 세 방 연속 플레이이며 한 사람당 최대 3회다.
- 첫 시도는 설명 없는 통합 관찰, 두 번째는 다른 폭탄·경로 시도 허용, 세 번째는 참가자가 확인하고 싶은 전략이 있을 때만 수행한다.
- 사망하거나 마지막 방을 끝낸 뒤 새 시도는 페이지 reload로 시작한다.

## 시작 안내

다음만 알려준다.

> 이동은 WASD 또는 방향키입니다. Z로 현재 폭탄을 설치하고 X로 두 폭탄을 교체할 수 있습니다. 각 방의 적을 모두 처치해 보세요. 피해를 최소화하면서 원하는 방식으로 플레이해 주세요.

- 돌진형의 색 의미, 정렬 조건, 파괴 블록의 최적 폭탄과 설치 위치는 설명하지 않는다.
- “유도하라”, “예고선에서 벗어나라”, “광역을 쓰라” 같은 전략 힌트를 주지 않는다.
- Esc는 아직 실제 pause 규칙이 아니므로 안내하거나 평가하지 않는다.

## 실행 순서

1. 세션 ID, commit, WebGL 산출물, 브라우저·해상도와 참가자 경험을 기록한다.
2. 첫 시도 전 `위 → 우` 빠른 반복과 각 키 해제 정지를 자유 이동 중 한 번 수행하게 하되, 좋고 나쁨을 암시하지 않고 느낌만 묻는다.
3. 첫 시도는 세 방을 끊지 않고 관찰한다. 방 전환 중 전략 힌트를 주지 않는다.
4. 피해·차저 첫 돌진·블록 파괴·슬롯 교체 직후의 행동을 기록하고, 시도 종료 뒤 의도를 질문한다.
5. 두 번째 시도 전에는 “다른 폭탄이나 경로도 시험해도 됩니다”만 말한다.
6. 필요할 때 세 번째 시도를 수행하고 직후 인터뷰를 마친다.
7. [전용 기록 템플릿](TwoEnemyBombChoiceSessionTemplate.md)에 사실·발언·해석과 `Keep / Change / Drop / Insufficient evidence`를 분리해 기록한다.

## 방별 관찰

| 방 | 기준선과 질문 |
|---|---|
| `loop` | 파괴 블록과 돌진형이 없는 추격자 기준선. 첫 폭탄, fuse 중 이동, 의도적 유도와 두 슬롯 자발적 교체 여부 |
| `lanes` | 대각선 파괴 블록 두 개. 같은 위치에서 십자와 광역의 결과 차이를 발견하는지, 블록을 열기 전후 퇴로가 달라지는지 |
| `pillars` | 중앙 파괴 블록과 두 적. 차저 예고를 처음 인지한 시점, 회피 방향, 돌진선·회복 위치를 이용한 선행 설치, 두 적 피해 원인 구분 |

“차저를 이용했다”는 우연히 폭발에 맞은 경우와 구분한다. 예고나 이동 종료를 본 뒤 설치 위치·타이밍·퇴로를 바꾸거나 그 의도를 설명한 경우에만 명확한 선행 계획으로 기록한다.

## 직후 인터뷰

1. 두 폭탄은 무엇이 달랐고 언제 바꾸고 싶었나요?
2. 파괴되는 블록을 남기거나 부술 때 각각 어떤 이점이 있다고 느꼈나요?
3. 마지막 방의 새 적은 공격 전에 무엇을 알려준다고 느꼈나요?
4. 그 적이 어디로 움직일지, 언제 다시 움직일지 예측할 수 있었나요?
5. 마지막 방에서 맞았다면 추격자·돌진·자기 폭발 중 무엇 때문이라고 생각하나요? 피할 수 있었다고 느꼈나요?
6. 키를 놓았을 때와 `상 → 우`를 빠르게 반복할 때 캐릭터가 손에 맞게 멈추고 꺾였나요?
7. 지금 한 번 더 한다면 폭탄 위치, 교체 시점 또는 이동 경로 중 무엇을 바꾸겠나요?

## 판정 기준

| 대상 | `Keep candidate` | `Change candidate` | `Drop/구조 재검토 후보` |
|---|---|---|---|
| 프레임 연속 이동 | 해제 즉시 정지하고 빠른 직교 반복이 누락 없이 느껴짐 | 특정 벽·셀 경계에서만 미끄러짐이나 꺾임 지연 | 평지에서도 이전 입력·관성이 반복 체감됨 |
| 두 폭탄 선택 | 방·블록·적 위치에 따라 설치 위치 또는 교체 시점이 달라짐 | 차이는 알지만 쿨타임·자기 위험 때문에 한 종류만 회피 | 외형만 다르고 같은 위치·순서로 해결하거나 교체가 무의미함 |
| 파괴 블록 | 남김/파괴가 엄폐·퇴로·폭발 선택의 실제 교환을 만듦 | 블록 효과는 있으나 색·파괴 시점 또는 배치가 혼란스러움 | 진행 방해물 또는 자동으로 부수는 장식일 뿐 선택이 없음 |
| 돌진 예고 | 첫 1~2회 안에 방향·시점을 읽고 이동 또는 선행 설치로 대응 | 위험은 알지만 방향 잠금·충돌 범위·회복을 오해 | 무작위 순간이동·피할 수 없는 피해로 반복 설명함 |
| 두 적 압력 | 원인을 구분하며 두 적을 서로 다른 이동·폭탄 계획으로 다룸 | 읽히지만 마지막 방 난이도 또는 시각 중첩이 과함 | 원인 불명 피해와 우연한 처치만 반복됨 |

소수 내부 세션은 최종 수치 확정 근거가 아니다. 두 해석이 가능하면 `Insufficient evidence`를 사용하고 다음 변경은 가장 강한 반복 증거 하나만 대상으로 한다.
