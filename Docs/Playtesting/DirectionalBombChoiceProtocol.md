## 고정 조건

- Unity 6000.5.3f1 Development WebGL, 10개 enabled 씬, seed 0. 960×600 네이티브 canvas는 browser viewport보다 클 때 16:10으로 축소되고 확대하지 않는다.
- 플레이어 이동 5 cells/s, 최대 체력 5, 자기 폭발·적 접촉 피해 1, 공유 무적 0.75초.
- 시작 `prototype-cross`: 십자, fuse 2초, 범위 2, 설치 쿨타임 1.5초.
- 왼쪽 `prototype-area`: 원점 주변 3×3, fuse 1.75초, 범위 1, 설치 쿨타임 2.5초.
- 오른쪽 `prototype-line`: 설치 순간 바라보기 방향으로 원점+앞 3셀, fuse 2.25초, 설치 쿨타임 2.25초.
- 교체 쿨타임 2초. 보상은 한 run에서 한 후보만 빈 슬롯 2에 장착된다.
- 일반 전투방은 루프·평행 통로·엇갈린 기둥·갑옷 실험선·중앙 게이트 중 seed 0 그래프에 배정되며, 보스 Recovery는 2.75초다.
- 보스는 현재 방 `LureLoop`를 따라 패턴마다 한 칸 이동한다. 시작 위치 `(0,1)`의 첫 목적지는 `(1,1)`이며 이후 `(1,0) → (1,-1) → (0,-1)` 순서다. Telegraph는 목적지 ghost와 위험 셀을 함께 보여 주고 목적지 영향 범위의 선행 폭탄은 이동을 막지 않는다.
- 선택형 Recovery leaf는 보스 전실 전에 한 번 방문할 수 있고 `+2`를 최대 체력까지 회복한다. 미니맵은 현재·방문·직접 인접 미방문 방과 확인된 연결만 표시한다.

세션 도중 수치, 코드, seed, 방 데이터와 설명 수준을 바꾸지 않는다. 다른 commit이나 빌드의 결과는 같은 조건으로 합치지 않는다.

## 참가자와 시도

- 내부 참가자 1~3명, 한 명당 15~25분.
- 시도 1은 첫 보상 후보를 자유롭게 선택하고 완료·사망 또는 참가자 중단까지 진행한다. 자연 선택 근거는 이 시도에서만 판정한다.
- 시도 2는 반대 후보를 사용한다. 후보 위치만 알려주고 추천 설치 위치·방·교체 순서는 알려주지 않는다.
- 시간이 허용되면 시도 3에서 참가자가 더 확인하고 싶은 후보를 자유롭게 고른다.
- 여러 참가자가 있으면 시도 2의 강제 후보 순서 효과를 줄이기 위해 첫 참가자는 자유 선택의 반대, 다음 참가자는 먼저 덜 관찰된 후보를 사용한다.
- 새 시도는 결과 화면의 `R` 재시작 또는 페이지 reload로 같은 seed의 초기 run 상태에서 시작한다.

## 시작 안내

다음만 알려준다.

> 이동은 WASD 또는 방향키입니다. Z로 현재 폭탄을 설치하고 X로 두 폭탄을 교체할 수 있습니다. 첫 전투 뒤 두 폭탄 중 하나를 선택할 수 있습니다. 방을 탐색하고 가능한 만큼 진행해 보세요.

- 직선·광역의 범위, 추천 방, 방향 고정과 쿨타임 차이는 설명하지 않는다.
- 후보 앞에서 망설일 때도 먼저 선택 기준을 묻지 않는다. 자발적 관찰·움직임·발언을 기록한 뒤 선택 직후 이유를 짧게 묻는다.
- 폭탄 설치 직전이나 fuse 중에는 질문하지 않는다. 설치 셀·바라보기·퇴로와 실제 반응을 먼저 기록한다.

## 이동 응답성 사전 확인

첫 시도의 시작방 중앙 통로에서 약 1분 동안 아래 순서만 수행한다. 이동 속도나 기대 결과를 먼저 설명하지 않고 정확한 입력 순서, 화면 motion과 참가자 발언을 분리해 기록한다. 이 확인은 폭탄 선택 가설과 별도 판정하며 세션 도중 수치나 코드를 바꾸지 않는다.

1. 빈 공간에서 위쪽 키를 약 0.3초 유지한 뒤 뗀다. 같은 동작을 오른쪽 키로 한 번 더 수행하고, 손을 뗀 뒤 더 미끄러진다고 느끼는지 묻는다. 벽까지 도달했다면 중앙으로 돌아와 다시 수행한다.
2. 중앙 쪽 여유 공간으로 돌아와 `상→우→상→우→상→우`를 짧게 누르고 매 입력에 화면 방향이 반응했는지 묻는다. 벽에 닿은 입력은 응답성 판정에서 제외하고 충돌 사실을 기록한다.
3. 벽을 향해 이동하다 벽과 평행한 직교 방향을 눌러 모서리를 두 번 돈다. 새 방향이 즉시 적용되는지, 이전 방향으로 끌리거나 예상하지 않은 셀로 진입하는지 기록한다.
4. 브라우저 focus 상실, frame drop, 벽 충돌과 키를 실제로 겹쳐 누른 경우를 가능한 교란 요인으로 별도 기록한다.

세 항목 모두 반복 재현 없이 자연스럽다면 방향 응답성을 `Supported`, 한 항목이 불분명하면 `Mixed`, 동일 입력에서 지연·추가 이동·입력 누락이 반복되면 `Not supported`로 기록한다. 한 사람의 체감만으로 이동 속도나 코너 보정 수치를 확정하지 않고, `Not supported`일 때 정확한 키 순서와 방·위치를 다음 단일 변경의 재현 계약으로 사용한다.

## 실행 순서

1. [로컬 WebGL 관찰 세션](ManualWebGLRun.md)에 따라 commit, 빌드, 브라우저·해상도와 Console 상태를 기록한다.
2. 시작방에서 위 이동 응답성 사전 확인을 수행한 뒤 일반 조작 학습, 기본 십자 설치 위치, 피해와 첫 클리어까지 관찰한다.
3. `BombReward`에서 접근 순서, 머문 시간, 후보 외형 확인과 자유 선택 이유를 기록한다.
4. 보상 뒤 각 전투방에서 아래 핵심 관찰표를 폭탄 설치마다 채운다. 의도는 설치 전 행동과 설치 직후 짧은 질문을 분리한다.
5. 직선 폭탄 사용 시 설치체가 가리킨 방향, 폭발 방향, 설치 뒤 이동 방향과 참가자의 예상이 일치하는지 기록한다.
6. 광역 폭탄 사용 시 자기 위험 범위, 파괴 블록 동시 적중, 적이 모인 정도와 퇴로를 기록한다.
7. 보스 입장부터 첫 Telegraph 목적지 ghost를 언제 인지했는지 기록한다. 전략 힌트 없이 첫 폭탄이 Execute 전에 목적지 영향 범위에 설치되는지, 이후 세 이동에서는 예고를 보고 설치 위치·시점을 바꾸는지 관찰한다.
8. Recovery에 들어간 뒤에만 현재 보스 옆에 설치한 경우도 성공/실패와 별개로 기록한다. 회피와 설치가 연결됐는지, ghost·위험 셀·보스 본체 중 무엇을 보고 판단했는지 패턴이 끝난 뒤 짧게 묻는다.
9. 시도 직후 인터뷰를 진행하고, 시도 2에서 반대 후보를 사용한다. 이동 응답성 사전 확인은 첫 시도에만 수행한다.
10. [전용 기록 템플릿](DirectionalBombChoiceSessionTemplate.md)에 관찰 사실·발언·해석과 `Keep / Change / Drop / Insufficient evidence`를 분리한다.

명확한 “상황별 폭탄 선택”은 설치 전에 공간·정렬·적 밀집·자기 위험 중 하나를 근거로 슬롯이나 설치 위치를 바꾸고, 참가자가 같은 이유를 말로 설명한 경우다. 설치 후 결과만 보고 이유를 만들어 낸 답변은 보조 증거로 둔다.

## 직후 인터뷰

1. 보상방에서 두 후보가 어떻게 다를 것이라고 예상했고, 왜 그 후보를 골랐나요?
2. 실제 사용 뒤 직선과 광역이 각각 유리한 방이나 상황을 설명할 수 있나요?
3. 직선 폭탄이 어느 방향으로 폭발할지 무엇을 보고 판단했나요? 설치 뒤 방향키를 바꾸면 결과가 바뀔 것 같았나요?
4. 한 폭탄을 고른 이유가 공간 때문이었나요, 쿨타임이 준비돼 있었기 때문이었나요?
5. 직선 폭탄은 정렬 보상이 충분했나요, 단순히 맞히기 어려운 약한 폭탄이었나요?
6. 광역 폭탄의 자기 위험과 설치 쿨타임은 강함에 대한 대가였나요, 사용을 방해했나요?
7. 보스 옆의 작은 청록 표시를 처음 무엇이라고 생각했고, 다음 위치를 언제 확신했나요?
8. 보스가 움직이기 전에 폭탄을 놓은 적이 있다면 어디에 왜 놓았나요? 없다면 무엇이 부족했나요?
9. 보스 패턴을 피하는 행동과 폭탄 준비가 연결됐나요, 서로 따로 느껴졌나요?
10. 보스 이동 빈도와 멈춰 있는 시간은 퓨즈를 계산하기에 어땠나요?
11. 두 폭탄 중 하나만 남긴다면 무엇을 남기고, 다른 하나를 바꾸려면 무엇을 바꾸겠나요?

| 공간 역할 차이 | 둘 이상의 방에서 정렬/밀집에 따라 슬롯 또는 설치 위치가 달라짐 | 차이는 말하지만 실제 행동은 한 방에서만 달라짐 | 항상 같은 폭탄·같은 근접 설치 또는 한 폭탄을 쿨타임 보조로만 사용 |

| 직선 체감 위력 | 복도·문·정렬 상황에서 위험을 감수할 이유가 생김 | 역할은 있으나 영향 셀·fuse·쿨타임 중 하나가 명확히 열세 | 대부분 상황에서 기본 십자보다 약하고 선택 이유를 설명 못 함 |
| 광역 위험/보상 | 모인 적·벽을 노리되 넓은 자기 위험 때문에 퇴로를 바꿈 | 강하지만 위험보다 쿨타임 답답함만 반복 언급 | 방 구조와 무관하게 가장 안전하거나 가장 강한 정답으로 고정 |
| 독립 쿨타임 | 공간 상황을 보고 기다리거나 교체 순서를 깨는 행동이 나옴 | 일부 선택은 있으나 대부분 준비 순서대로 사용 | A→B 고정 로테이션만 반복하고 모양은 사실상 무관 |
| 보스 이동·선행 설치 | 첫 1~2회 안에 ghost 목적지를 읽고 Execute 전에 영향 범위·퇴로를 계획함 | 이동은 읽지만 Recovery 이후 근접 설치가 대부분이거나 우연한 적중과 계획이 섞임 | 목적지를 읽지 못하거나 계속 움직여 맞힐 수 없다고 느끼며 패턴 회피와 공격이 분리됨 |

소수 내부 세션은 수치 확정 근거가 아니다. 먼저 반복되는 가장 큰 문제 하나만 `Change candidate`로 올리고, 영향 셀·fuse·쿨타임·방 배치를 동시에 바꾸지 않는다.
