# 첫 기본 전투 관찰 플레이테스트

- 상태: `Ready`
- 대상 기준: 3방 시퀀스가 포함된 고정 commit/build를 세션 기록에 명시
- 대상 방: `prototype-combat-loop` → `prototype-combat-lanes` → `prototype-combat-pillars`
- 연결 가설: `ProtoType_v0.2.md` 가설 A, 테스트 1

## 이번 세션이 답할 질문

1. 플레이어가 폭탄을 놓은 뒤 멀리 기다리지 않고 추격자를 폭발 범위로 유도하는가?
2. 설치된 폭탄을 공격 수단이자 임시 벽으로 인식하는가?
3. 중앙 루프, 평행 통로, 엇갈린 기둥에서 서로 다른 퇴로와 유도 경로를 선택하는가?
4. fuse 2초 동안 이동·유도 판단이 이어지는가, 기다리는 시간이 지루한가?
5. 접촉 피해, 자기 폭발과 무적 0.75초가 공정하고 원인을 설명할 수 있는가?
6. 보상·성장 없이 세 방을 끝낸 뒤 다른 경로로 즉시 다시 시도할 의지가 있는가?

자동 테스트가 보장하는 것은 규칙의 결정론과 연결 정상 여부뿐이다. 위 질문은 실제 사람의 행동과 발언이 있어야 판단한다.

## 고정 빌드와 현재 수치

- Unity 6000.5.3f1 Development WebGL 3방 빌드 또는 같은 commit의 세 TestSandbox 씬.
- 플레이어 이동 5 cells/s, 추격자 이동 2 cells/s, 방향 유지 2칸.
- 기본 십자 폭탄 fuse 2초, 범위 2.
- 플레이어 최대 체력 5, 자기 폭발/접촉 피해 1, 공유 무적 0.75초.
- 추격자 내구도 1, 접촉 피해 1.
- 방 구조와 좌표는 [방 저작과 검증](../Systems/RoomAuthoring.md)의 현재 수제 전투방 세트를 사용한다.

세션 기록에는 commit과 실행 환경을 반드시 남긴다. 빌드가 다르면 같은 조건의 결과로 합치지 않는다.
로컬 WebGL 빌드를 실행하고 build reference·브라우저 로그를 남기는 절차는 [로컬 WebGL 관찰 세션 실행](ManualWebGLRun.md)을 따른다.

## 참가자와 시간

- 첫 내부 세션: 1~3명, 한 명당 10~15분.
- 한 번의 시도는 세 방 연속 플레이를 뜻하며 한 사람당 최대 3회 시도한다. 사망하거나 마지막 방을 클리어한 뒤 다시 시도하려면 현재 프로토타입을 reload/restart한다.
- 이 표본은 방향을 찾는 용도다. 한 명의 성공이나 실패만으로 수치를 확정하지 않는다.

## 시작 안내

다음만 알려준다.

> 주황색 캐릭터를 이동해 각 방의 초록색 추격자를 폭탄으로 처치하세요. 이동은 WASD 또는 방향키, 폭탄 설치는 Z입니다. 피해를 최소화해 보세요.

- X와 Esc는 현재 실제 교체·pause 규칙이 없으므로 설명하지 않는다.
- “적을 유도하라”, “벽을 돌아라”, “왼쪽으로 도망가라” 같은 전략 힌트는 주지 않는다.
- 조작을 잊은 경우 키만 다시 알려주고 해결법은 말하지 않는다.

## 실행 순서

1. 세션 ID, commit, 환경, 참가자의 유사 장르 경험을 기록한다.
2. 첫 시도는 세 방을 끊지 않고 개입 없이 관찰한다. 진행자는 생각을 소리 내도록 강요하지 않는다.
3. 각 방의 전환 시점과 사망 또는 마지막 방 클리어 직후 행동을 먼저 기록하고, 시도 종료 뒤 원인과 의도 및 재시도 의향을 묻는다.
4. 참가자가 원하면 최대 두 번 더 시도한다. 두 번째부터는 “다른 방법도 시험해도 된다”만 말한다.
5. 마지막 시도 뒤 짧은 인터뷰를 진행한다.
6. 사실/발언/해석을 분리해 템플릿을 완성하고 아직 판단할 수 없는 항목은 `Insufficient evidence`로 남긴다.

## 시도별 관찰 항목

| 항목 | 기록 방식 |
|---|---|
| 방 | `loop` / `lanes` / `pillars`; 같은 행동도 방별로 분리 |
| 첫 폭탄까지 | 대략적인 초 또는 즉시/탐색 후 |
| 설치 위치와 적 위치 | 셀을 알 수 있으면 좌표, 아니면 화면상 상대 위치 |
| fuse 동안 행동 | 유도 이동 / 퇴로 이동 / 안전 지대 대기 / 방향 상실 |
| 유도 시도 | 적의 이동을 보고 폭발 셀로 끌어들인 명확한 행동과 발언 |
| 폭탄의 벽 효과 | 적 길막 또는 자기 퇴로 차단이 발생했는지 |
| 퇴로 | 좌·우·순환·되돌아감·사실상 한 경로 |
| 피해 | 접촉 / 자기 폭발 / 원인 불명, 발생 직후 반응 |
| 무적 체감 | 연속 피격이 과함 / 납득 / 너무 관대함 / 인지 못함 |
| 결과 | 클리어 / 사망 / 중단, 대략적인 시간과 폭탄 수 |
| 전환 | 다음 방을 즉시 인지 / 혼란 / 준비 부족, 1.25초 지연에 대한 반응 |
| 재시도 | 자발적 / 질문 뒤 동의 / 거절, 이유 원문 |

“유도했다”는 단순히 적이 우연히 폭발에 들어온 경우와 구분한다. 플레이어가 적 이동을 확인하고 위치나 경로를 바꾼 행동 또는 그 의도를 설명한 경우에만 명확한 유도로 기록한다.

## 직후 인터뷰

질문은 답을 유도하지 않고 아래 순서로 묻는다.

1. 방금 무엇을 하려고 했나요?
2. 가장 재미있거나 긴장된 순간은 언제였나요?
3. 폭탄을 놓은 뒤 무엇을 기다리거나 계산했나요?
4. 피해를 받았다면 무엇 때문에 맞았다고 생각하나요? 납득됐나요?
5. 도망갈 길은 몇 개로 느껴졌고 왜 그 길을 골랐나요?
6. 지금 바로 한 번 더 한다면 무엇을 다르게 해보고 싶나요?

참가자의 표현을 요약만 하지 말고 짧은 핵심 문장은 원문으로 기록한다.

## 유지·변경·제거 판단 기준

| 대상 | 유지 근거 | 변경 검토 근거 | 구조 재검토 근거 |
|---|---|---|---|
| 기본 유도 루프 | 의도적 유도와 fuse 중 위치 조정이 반복 관찰됨 | 유도 의도는 있으나 속도·fuse 때문에 자주 빗나감 | 기다리기만 하거나 적이 우연히 맞는 해결만 반복됨 |
| 세 방 구조 | 방별로 둘 이상의 퇴로를 인식하고 구조에 따라 경로를 바꿈 | 다른 길은 보이지만 특정 통로나 방이 일관되게 불리함 | 세 방이 같은 해결로 느껴지거나 핵심 루프·통로·기둥이 사용되지 않음 |
| 폭탄 임시 벽 | 길막을 계획적으로 이용하고 자기 차단도 이해함 | 효과는 알지만 판정 시점이나 표현이 혼란스러움 | 폭탄 점유가 보이지 않아 피해·막힘 원인을 설명하지 못함 |
| 접촉·무적 | 피해 원인을 즉시 설명하고 회피 가능했다고 느낌 | 원인은 알지만 반복 피해 간격이 너무 짧거나 김 | 피할 수 없거나 무작위 피해라고 반복해서 설명함 |
| 재도전 가치 | 성장 없이 자발적으로 다른 방법을 시도함 | 질문 뒤에는 재시도하지만 목표가 불명확함 | 같은 해결 반복만 예상하거나 즉시 재시도를 거절함 |

첫 1~3명 세션에서는 최종 통과 선언보다 `Keep candidate`, `Change candidate`, `Drop candidate`, `Insufficient evidence`를 사용한다. 두 가지 이상 해석이 가능한 관찰은 영상과 발언을 다시 보고 보수적으로 분류한다.

## 증거 산출물

원본은 다음처럼 Git 제외 경로에 둔다.

```text
Artifacts/Playtests/PT-YYYYMMDD-01/
  session-notes.md
  attempt-01.mp4
  attempt-02.mp4
  browser-console.txt
  build-reference.txt
```

결과를 합의하면 [세션 기록 템플릿](SessionTemplate.md)으로 익명 요약을 만들고 `Docs/Playtesting/Results/PT-YYYYMMDD-01.md`에 보존한다. 원본 파일이 없으면 `not captured`와 이유를 명시한다.

## 이번 프로토타입의 제한

- 방 클리어 뒤 1.25초 후 자동으로 다음 방을 로드하며 중간 보상·요약·준비 화면이 없다. 세 번째 방은 클리어 상태로 머문다.
- 재시작 UI, 완성 HUD·오디오, 실제 무기 교체·pause가 없다.
- WebGL probe는 사건 존재를 확인하지만 전체 설치·이동 횟수와 의도를 기록하지 않는다.
- 추격자는 하나이고 국소 Manhattan 이동이므로 복잡한 경로 탐색 가설은 대상이 아니다.
