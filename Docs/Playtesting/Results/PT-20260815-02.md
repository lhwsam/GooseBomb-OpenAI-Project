## 증거 품질

참가자가 이전에 보고한 세 가지 이동 재현 절차를 같은 수정 build에서 직접 다시 확인했다. 키 해제, 빠른 직교 반복과 벽 모서리 전환의 회귀 판정은 명시적 사용자 확인이 있어 신뢰도가 높다. 그 외 네 항목은 플레이 중 느낀 서술형 피드백이며 방별 행동 기록, 폭탄별 설치 근거, 완료 여부와 직후 세부 인터뷰가 없어 재미 가설의 최종 통과 근거로 사용하지 않는다.

## 유지·변경·보류 결정

- `Keep`: frame 연속 이동과 현재 직교 방향 우선 정책. 보고된 세 입력 결함을 다시 수정하지 않는다.
- `Modify first`: 방 전환 뒤에도 직전 활성 폭탄 슬롯을 run 상태에서 복원한다.
- `Implemented, validate next`: 방문 방·현재 방·직접 인접 미방문 방과 확인된 연결만 표시하는 [최소 미니맵 수직 슬라이스](../../Development/MinimalMinimapSlice.md)를 구현했다. 전체 미탐색 지형 공개나 fast travel은 넣지 않았으며 길 찾기 피로 감소는 다음 사람 플레이에서 판정한다.
- `Implemented, validate next`: Telegraph→Execute→Recovery를 유지하면서 `LureLoop` 한 칸 이동, 목적지 ghost와 선행 폭탄 적중을 구현했다. 실제 이해·재미는 다음 사람 플레이에서 판정한다.
- `Complete`: 활성 슬롯과 체력의 run persistence, [GDD 기반 회복방](../../Development/RecoveryRoomSlice.md)의 보스 근처 선택형 막다른 방과 제한 정보 미니맵을 구현했다. 적 처치 확률 드롭은 제외한다.
- `Insufficient evidence`: 광역·직선 폭탄의 역할 차이, 갑옷 첫 피격 가독성과 독립 쿨타임의 재미는 다음 플레이에서 계속 관찰한다.
