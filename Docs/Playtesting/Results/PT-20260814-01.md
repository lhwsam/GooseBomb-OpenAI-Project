## 증거 품질

참가자가 세 방 플레이를 완료하고 서술형 피드백을 제공했다. 영상, 방별 행동 타임라인, 설치 횟수, 피해 원인 응답과 상세 직후 인터뷰는 수집하지 못했다. 따라서 기본 폭탄 유도, 퓨즈 동안의 행동, 퇴로 선택과 방별 전투 차이는 이번 세션만으로 판정하지 않는다.

방향 전환 문제는 참가자 발언에 더해 현재 구현을 같은 입력값으로 실행한 Unity 재현과 수정 전 실패 회귀 테스트로 보강했다. 이 결함에 관한 증거 신뢰도는 다른 재미 가설보다 높다.

## 관찰과 해석

| 구분 | 내용 |
|---|---|

| 참가자 평가 | 방향 전환 외에는 현재까지 개발된 내용이 괜찮다고 느꼈다. |
| 참가자 재검증 조건 | 폭탄과 상호작용하는 블록 등이 추가된 뒤 전투 느낌을 다시 확인할 필요가 있다. |

## 유지·변경·보류 결정

- `Keep candidate`: 현재 기본 폭탄, 세 방, 추격자와 피해 규칙은 이번 세션만으로 제거하거나 수치를 바꾸지 않는다.
- `Modify`: 서로 직교하는 두 cardinal 키가 겹치는 방향 전환에서 이전 방향 대신 새 방향을 우선한다.
- `Keep`: 논리 이동 cadence와 셀 경계 전환은 이번 수정에서 그대로 두어 원인을 하나씩 비교한다.
- `Defer and retest`: 파괴 가능 벽이나 폭탄 상호작용 블록이 추가된 뒤 폭탄의 통로 제어와 방별 해결 차이를 다시 관찰한다.
- `Insufficient evidence`: 이번 세션을 근거로 가설 A 통과나 두 슬롯·독립 쿨타임의 재미를 선언하지 않는다.

## 1차 수정 build 수동 재확인

- build commit: `069c446`
- 참가자 관찰: 문제는 줄었지만 여전히 어색했다. 위쪽을 계속 누른 채 오른쪽을 짧게 누르면 오른쪽 한 칸 뒤 위쪽으로 복귀해야 하는데 계속 위쪽으로만 가는 현상이 있었다.
- 해석 전 기술 재현: `North` 첫 step 뒤 50ms에 `East`, 다시 50ms 뒤 `North`를 전달하고 100ms 뒤 다음 step을 실행하면 실제 방향이 `East`가 아니라 `North`였다.
- 갱신 판정: 방향 전환 응답성은 여전히 `Not supported`. 1차 tie-break 수정은 명령 우선순위 문제를 줄였지만 cadence 사이의 짧은 입력 유실을 해결하지 못했다.
- 결정: 이동 속도·step 간격·Transform 보간은 유지하고, Core가 최신 직교 방향 1개를 다음 step까지 보존하는 단일 변수만 추가한다.
- 다음 관찰: `위 유지 → 오른쪽 짧게 누름과 해제`를 반복해 실제 오른쪽 한 칸 뒤 위쪽 복귀가 안정적으로 보이는지 확인한다.

## 2차 수정 build 수동 재확인

- build commit: `1b2547b`
- 참가자 관찰: 방향 전환은 여전히 어색했다. 키를 놓아도 조금 더 이동한 뒤 멈추는 느낌이 있었고, `상 → 우 → 상 → 우 → 상 → 우`를 빠르게 반복하면 즉시 반응하지 않는다고 느꼈다.
- 갱신된 원인: 5 cells/s를 한 셀당 0.2초 예약 step으로 바꾸고, step 시작에 목적 셀을 확정한 뒤 Transform이 그 셀까지 0.2초 보간한 구조였다. pending turn은 단일 짧은 전환은 보존했지만 빠른 반복을 합치며, 키 해제 뒤에도 이미 확정한 셀 이동을 끝냈다.
- 수정 전 실패 증거: PlayMode에서 키 해제 시 표시 위치 `z=0.292967051`이 0.15초 뒤 `z=1.0`까지 계속 진행했다.
- 결정: 기본 5 cells/s와 정수 격자 판정은 유지하고, 플레이어 위치를 Core 연속 `GridSubcellPosition`으로 소유해 매 frame 경과 시간을 직접 반영한다. 별도 0.2초 플레이어 cadence, pending turn과 Unity 목적 셀 보간은 제거한다.
- 갱신 판정: 방향 전환 응답성은 구조 수정 자동 검증을 통과했지만 참가자 수동 재확인 전까지 `Not supported`를 유지한다.
