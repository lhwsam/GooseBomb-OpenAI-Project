## 관찰과 증거 품질

참가자는 보스 무적 구간과 과열당 피해 상한을 제거한 빌드를 플레이한 뒤 “좋고 재미있는 것 같다”고 평가했다. 직전 빌드에서는 난이도가 충분히 높아졌으므로 제한된 피해 창이 더 이상 필요하지 않다고 요청했고, 상시 피해 변경 뒤에는 추가 난이도 하향이나 수치 변경을 요구하지 않았다.

이는 같은 참가자의 변경 전후 직접 비교이므로 상시 피해 허용 방향을 유지할 근거는 된다. 다만 플레이 경로, 전투 시간, phase별 피격, 공격 상태별 보스 적중, 두 슬롯 교대와 자폭병 유도 행동이 기록되지 않아 보스 가설 전체의 통과 근거로는 부족하다. 방향 신뢰도는 중간, 세부 수치와 행동 가설 신뢰도는 낮다.

## 결정

- `Keep`: 살아 있는 보스의 Telegraph / Execute / Recovery 상시 피해와 서로 다른 `BombId`별 피해 1.
- `Keep`: 과열을 유일한 취약 창이 아닌 공격 주기의 휴식 구간으로 사용하고 과열당 피해 상한을 두지 않는다.
- `Do not tune yet`: 체력, 투척 간격, 과열 시간과 phase 임계값. 긍정적 한 문장만으로 추가 난이도·시간을 조정하지 않는다.
- `Measure next`: 보스 프로토콜의 자동 계측과 관찰 질문을 함께 사용해 같은 commit 계열의 고정 WebGL 세션을 기록한다.
