# 프로토타입 권장 개발 순서

- 상태: `Accepted`
- 권위 가설: `Docs/GameDesign/ProtoType_v0.2.md`

각 단계는 다음 단계의 기반이 아니라 하나의 검증 가능한 수직 슬라이스로 끝나야 한다. 자동 테스트 통과와 재미 가설 통과를 구분한다.

## 현재 게이트

1~5단계의 GDD 필수 구현은 완료됐지만 재미 가설은 완료되지 않았다. 요구사항별 근거와 남은 사람 판정은 [프로토타입 준비도 감사](PrototypeReadinessAudit.md)를 따른다. 6단계 패시브 아이템은 기본 전투·두 폭탄 역할의 사람 증거가 지지되기 전에는 시작하지 않는다.

실제 플레이에서 반복적인 설치→외곽 도주→대기가 관찰되어 [전투·적 AI·레벨·보스 개선 제안](../GameDesign/CombatEnemyLevelBossImprovementProposal.md)을 후속 `Proposed` 백로그로 채택했다. 비밀벽 정렬→추격자 BFS→돌진형 차선 획득→장갑병 panic run까지 규칙 구현과 자동·WebGL 검증을 완료했고, 현재 게이트는 장갑병 방향 가독성과 두 번째 선행 설치의 사람 검증이다. 그 증거가 지지되면 자폭병/Gates→전용 보스방 순서로 진행한다.

## 0. 개발 기반

- AGENTS, 문서 권위, 폴더/asmdef.
- AI 스킬과 검증 하네스.
- Unity compile, EditMode, PlayMode, WebGL build의 반복 가능한 실행 경로.
- 테스트 샌드박스와 최소 계측.

종료 조건: 다른 세션이 문서만으로 현재 상태와 다음 작업을 찾아 동일한 검증을 실행할 수 있다.

## 1. 기본 십자 폭탄 단독

- 논리 격자, 이동/점유 최소 계약.
- 폭탄 설치, fuse, 십자 폭발, 벽 차단.
- 자기 피해와 설치 직후 통과.
- 3D placeholder 표현과 WebGL 입력.

가설: 폭탄 설치 후 기다리기만 하지 않고 이동·유도 플레이가 이어진다.

## 2. 두 폭탄 고정 조합

- 두 슬롯, 교체, 독립 설치 쿨타임.
- 기본/직선 또는 기본/광역 조합.
- 슬롯·쿨타임 UI와 위치 선택 계측.

가설: 두 폭탄이 서로 다른 위치와 시점을 요구하며 고정 로테이션만 만들지 않는다.

## 3. 횟수제 적

- 추격자, 돌진형, 갑옷 적.
- 피격 단계, 무적, 사망/방 클리어.

가설: 여러 번 맞혀야 하는 적이 폭탄 적중의 쾌감을 해치지 않는다.

## 4. 한 층 그래프

- 수제 방 5~7개와 검증기.
- seed 기반 3~5 전투방 그래프.
- 첫 두 번째 폭탄 보상, 보스 전실/보스 경로.

가설: 방 배열 변화가 탐색 동기를 만들고 불공정한 입장을 만들지 않는다.

## 5. 보스

- 격자 예고 패턴 2개 이상.
- 회피 후 반격과 phase 변화.

가설: 보스전이 핵심 폭탄 게임의 종합으로 느껴진다.

## 6. 선택 범위

시간이 남을 때만 패시브 아이템 최소 세트와 추가 방 유형을 검토한다. 핵심 가설이 실패한 상태에서 콘텐츠 양으로 문제를 덮지 않는다.
