# ADR-0007: 잠재 방 출구와 run 활성 문의 분리

- 상태: `Accepted`
- 날짜: 2026-08-14
- 결정자: 프로젝트 팀

## 맥락

`prototype-tree-v1`은 seed에 따라 직선, 코너와 3갈래 전투 노드를 만든다. 512개 연속 seed를 측정한 결과 전투방 2,291개 중 막다른 방 512개, 직선 643개, 코너 802개, 3갈래 334개였다.

기존 네 수제 전투방은 서로 마주 보는 두 출구만 저작했다. 회전만으로는 코너와 3갈래 노드에 배정할 수 없으며, 그래프 방향과 실제 문 방향을 다르게 매핑하면 이동과 미니맵의 공간 문법이 깨진다.

## 결정

- 방 정의의 `Exits`는 항상 열린 문이 아니라 해당 방 geometry가 지원하는 잠재 출구다.
- 현재 네 11×9 전투방은 중앙 경계 셀의 북·동·남·서 잠재 출구를 각각 한 개씩 저작한다.
- run 배정은 그래프 노드의 연결 방향을 활성 출구 부분집합으로 선택한다. 사용하지 않는 잠재 출구는 실제 문 어댑터가 닫힌 경계로 표현해야 한다.
- 수제 방은 0/90/180/270도 시계 방향 회전을 허용한다. Unity Y축 양의 회전과 `North → East → South → West` 방향 순서를 일치시킨다.
- 콘텐츠 배정은 topology 생성과 분리된 고정 salt RNG를 사용하고 `prototype-combat-assignment-v1`으로 버전 관리한다.
- 입력 카탈로그 순서와 무관하게 안정 room ID로 정렬하며, 호환되는 방 사이에서 사용 횟수가 가장 적은 정의를 먼저 선택한다.
- 어떤 회전으로도 활성 출구를 지원하지 못하면 배정 실패를 명시적으로 보고한다. 그래프 방향을 다른 물리 문에 임의로 연결하지 않는다.

## 대안

- 생성기를 기존 직선 2출구 방에 맞춘다: 현재 콘텐츠에는 빠르지만 코너·분기 seed 다양성과 향후 비밀방 확장을 과도하게 제한한다.
- 그래프 방향과 실제 문 방향을 무관하게 매핑한다: 구현은 단순하지만 방향키 이동과 미니맵의 기대를 위반한다.
- 코너·3갈래 prefab만 별도로 추가한다: 장기 콘텐츠 다양성에는 유효하지만 현재 네 방 내부를 복제하는 비용이 크고 프로토타입 배정 검증을 지연한다.

## 결과

- 현재 네 수제 방만으로 모든 프로토타입 전투 노드 차수를 지원할 수 있다.
- 잠재 출구 수와 실제 열린 문 수가 다르므로 Unity 문 시스템은 그래프의 활성 부분집합을 권위 원본으로 사용해야 한다.
- TestSandbox 경계 벽과 선형 전환은 아직 잠재 출구를 실제 문으로 표현하지 않는다.
- 향후 room variant가 출구 일부만 지원해도 같은 호환 검사와 회전 계약을 재사용할 수 있다.

## 검증 및 철회 조건

- 같은 그래프·카탈로그는 입력 배열 순서와 무관하게 동일 배정을 만든다.
- 모든 활성 방향은 회전된 저작 출구에 존재하고, 모든 전투 노드는 정확히 한 번 배정된다.
- 네 실제 room asset은 cardinal 잠재 출구를 방향별 한 개씩 가진다.
- 활성 문을 닫고 여는 표현이 플레이어에게 혼동을 주거나 네 방향 출구가 방 내부 전투 의도를 훼손하면 코너·분기 전용 variant 추가를 우선 재검토한다.
