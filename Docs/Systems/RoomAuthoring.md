# 방 저작과 검증

- 상태: 수제 방 프리팹 원칙 `Accepted`, 메타데이터 스키마 `Proposed`
- 설계 원본: `GDD_v0.2.md` 19, 21~23장
- 코드 소유: `BombSwap.Authoring`, `BombSwap.Editor`

## 목적

전투 공간은 사람이 설계하고, 런 구조만 절차적으로 조합해 공정성과 폭탄별 공간 차이를 함께 확보한다.

## 권장 프로토타입 범위

- 전투방 프리팹 5~7개.
- 시작방, 일반 전투방, 첫 폭탄 보상, 보스 전실, 보스방.
- 보물/회복/비밀방은 시간이 남을 때 또는 프로토타입 이후.

## 방 메타데이터

최종 스키마는 구현 시 확정하지만 최소한 다음을 검증 가능하게 표현한다.

- 안정적인 room ID와 room type.
- 격자 크기, 셀 크기, 원점.
- 출입구 위치와 방향.
- 고정 벽/파괴 가능 벽 셀.
- 플레이어 입장 안전 영역.
- 적 spawn 후보와 제약.
- 보상/전환 anchor.

## 저작 불변식

- 입구 즉사 위험이 없다.
- 일반 전투방은 가능한 한 최소 두 개의 퇴로와 짧은 순환 경로를 제공한다.
- 폭발을 끊는 벽/기둥이 읽히고 파괴 가능 벽이 명확하다.
- 최소 두 폭탄 역할이 서로 다른 위치 선택을 만들 여지가 있다.
- 출입구 셀과 플레이 가능 셀이 연결되어 있다.
- 프리팹 Transform 배치와 논리 메타데이터가 일치한다.

## Editor 검증기

방 저장 또는 명시적 검증 시 다음을 보고한다.

- 중복 room ID, 범위 밖 셀, 겹치는 셀 타입.
- 누락된 입구, spawn, 필수 anchor.
- 연결되지 않은 플레이 영역과 막힌 출구.
- 프리팹 참조 누락과 잘못된 레이어/컴포넌트.
- 권장 규칙 위반은 경고, 실행 불가능한 데이터는 오류로 구분한다.

자동 검증이 방의 재미를 보증하지는 않는다. 시각 확인과 플레이테스트를 함께 수행한다.
