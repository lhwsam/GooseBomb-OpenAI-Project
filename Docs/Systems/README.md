# 시스템 문서 작성 규칙

`Docs/Systems/`는 구현 세부가 아니라 플레이어에게 보이는 동작과 시스템 간 계약을 설명한다. 한 시스템의 규칙을 여러 문서에 복제하지 말고 권위 문서로 연결한다.

## 문서 템플릿

```markdown
# 시스템 이름

- 상태: Accepted | Proposed | Deferred
- 설계 원본: GDD 절 링크
- 코드 소유: 어셈블리/폴더

## 목적
## 플레이어에게 보이는 동작
## 책임과 비책임
## 용어와 데이터
## 상태와 전이
## 처리 순서
## 불변식
## Unity 연결
## WebGL 고려사항
## 자동 테스트
## 플레이테스트 관찰
## 미정 사항과 종료 조건
## 관련 문서
```

## 작성 원칙

- `Accepted`, `Proposed`, `Deferred`를 명시한다.
- 수치는 확정값과 가설값을 구분한다.
- 상태 소유자와 최종 판정자를 적는다.
- 실패·경계 상황과 회귀 테스트를 함께 적는다.
- 사람이 이해할 수 있는 용어를 먼저 쓰고 실제 타입 이름은 구현된 뒤 연결한다.
- 구현 변경으로 계약이 바뀌면 같은 변경에서 문서를 갱신한다.
